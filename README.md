# HRBP-AI · 人力预算与预估管理平台

把 HRBP 每月「多系统人工取数 → 线下 Excel 对齐 → 手工出表」的工作搬上 Web：
**自动汇集数据 → 自动计算预估、出表 → 人只做确认和调节。**

| | |
|---|---|
| 技术栈 | FastAPI + SQLite + 单文件前端（原生 JS，无构建） |
| 组成 | `index.html`（看板）· `admin.html`（管理后台）· `backend/`（API，9 个模块 3731 行） |
| 规模 | 26 个部门 / 256 个中心 · 53 个 API 路由 · 4 个业务看板 |
| 登录 | iOA 占位（`X-User` 头），正式版接 iOA 统一登录 |

---

## 一、业务背景

**人力预算**：每年 9 月根据业务需求与公司成本管控要求，制定下一年**每个月**的在岗人数作为预算。实际执行的基本要求是两条硬约束：

1. 全年实际平均在岗 ≤ 预算全年平均在岗（by 月在岗相加 ÷ 12）
2. 12 月实际在岗 ≤ 预算 12 月在岗

**人力预估**：次年执行过程中，BP 需定期根据实际的人力流入、流出节奏刷新部门 by 月的人力预估，并记录已发生月份的实际在岗，动态监控 by 月变化、调整流入流出节奏，确保全年平均在岗与年末在岗满足预算规划。

**痛点**：数据分散在多个系统且未能实时准确更新，BP 仍需大量时间线下用 Excel 与各方对齐。

## 二、核心设计原则

### 识空引擎（高压线，不可协商）

**所有数字必须由真实数据源提供。数据源未接入或库中无值时，单元格一律留空——绝不编造、绝不补零。**

这条约束贯穿前后端，且**具备传染性**：

- 缺源数据时，其合计、预估链、年均等派生值**同样留空**，不会用 0 参与运算
- 服务端与前端采用同一套识空口径，不存在"前端看着有数、后端其实是空"
- 假数据必须显式标示：走假数库时页面顶部强制显示「示例」横幅（`is_demo_db()`）

### 运算不落库

预估链、自然流失、GAP、年均等派生值**实时计算、不写库**（`calc_kb1.py`）。库里只存源数据与人工填写值，避免"改了源数据但派生值没刷新"的脏数据。

### 估实双轨

已发生月走**实际口径**、未发生月走**预估口径**，以「锁定月」为分界。已确认月份的数据不会被源数据变化自动改写——差异进入 diff 面板由人决定采纳或留案。

### 依赖

```bash
pip install fastapi "uvicorn[standard]" python-multipart
```

其余全部为 Python 标准库（`sqlite3` / `csv` / `zipfile` / `xml` 等），无额外依赖。

### 启动

```bash
cd backend
PYTHONPATH=. python -m uvicorn app:app --port 8787
```

|---|---|
| http://127.0.0.1:8787/ | 看板（index.html） |

## 五、组织层级与用工口径

**这是理解整个系统的前提，两个概念必须分清。**

### 组织层级（纵向，四层）

```
业务线（2 条）                       虚拟分组·若干【部门】的组合·只读求和
   ↓
部门（26 个）                        org_depts·真实层级·只读汇总
   ↓
中心（256 个）                       org_centers·BP 主录入层·可录入
   ↓
个人                                 accounts.dept_id / center_id
```

两条业务线正好覆盖全部 26 个部门：

| 业务线 | 负责人 | 部门数 |
|---|---|---|
| coby线 | 邱跃鹏 | 11（云产品一部、云产品五部、战略客户部、智慧行业一/七/十部、云运营管理部、云采购供应管理部、星星海实验室、港澳台及国际业务部、CSIG产品管理支持中心） |
| wang线 | 王慧星 | 15（云产品二/三/四/六部、安全产品一/二/三部、科恩/玄武/优图实验室、企业中台产品部、云产品技术支持部、云技术运营服务部、社交协作产品部、ima产品中心） |

### 用工口径（横向，三种**并列**）

**部门之下，是三种并列的用工口径，彼此不是上下级关系：**

| 口径 | 含义 | 对应看板 | 是否细到中心 |
|---|---|---|---|
| **集团（本部/自有）** | 管理主体 = 腾讯集团本部 | 集团人力预估表、预算看板、社招滚动台账 | ✅ 256 个中心 |
| **云智** | 云智子公司用工 | 云智 & 外包 | 当前仅到部门级 |
| **外包** | 外包用工 | 云智 & 外包 | 当前仅到部门级 |

### ⚠ 「集团」一词有两个含义，别混

| | 含义 | 说明 |
|---|---|---|
| ① | **用工口径** | 部门内的集团本部/自有员工，与云智、外包**并列** |
| ② | **空间键 `dept="集团"`** | 全部门该口径的**合计**，界面显示「合计（各部门加总）」，只读 |

含义 ② 是一个汇总空间键，**不是**组织层级的顶层。

### 虚拟空间（组织表里没有这一层）

| 空间 | 键格式 | 组成 | 可写性 |
|---|---|---|---|
| 业务线 | `LINE:线名` | 若干**部门**的人为分组 | 只读求和，仅线级调节项可填 |
| 子PM组 | `PM:部门:组名` | 若干**中心**的人为分组 | 只读求和，仅本组调节项可填 |

两者都是「先加总后运算」：先把成员空间的源数据逐月相加，再在合计上跑运算链——不是把各成员的运算结果相加。

## 六、功能地图

### 看板（侧栏「看板」组）

| 看板 | 说明 |
|---|---|
| **集团人力预估表**（主看板） | 核心页面。逐月指标行 × 12 个月，含预算当量 / 期末在岗 / 各类流入流出 / GAP / 流失率。支持集团合计、部门、中心、业务线、子PM组五种空间 |
| **预算看板** | 逐月「期初 vs 现行」对比，含求和与 ⊕ 自定义分支 |
| **社招滚动台账** | 3.1 招聘需求面板 + 3.2 待流入·社招（分中心维度）。支持 xlsx/csv 导入，与主看板逐行一致 |
| **云智 & 外包** | 两张表，结构同主看板。与集团本部**并列**的用工口径，HC 与预算当量由 BP 手填 |

主看板运算链：

```
本月期末在岗 = 上月期末在岗 - 当月总流出 + 当月总流入
```

- 已发生月用实际口径，未发生月用预估口径，以锁定月分界
- 自然流失预估 = 近 n 月 ER 均值取整（`int(合计 ÷ n + 0.5)`，跨年窗口，缺数不派生）
- GAP = 预估年均 − 预算年均

### 辅助视图

除 4 个看板外，还有数据源状态、审计日志、PRD 覆盖清单、AI 助手（RAG 问答）、体验说明等视图（`goView()` 切换，容器 `v-ds` / `v-audit` / `v-cov` / `v-ai` / `v-ux`）。

### 管理后台（admin.html）

| 模块 | 能力 |
|---|---|
| **账号与权限** | iOA 账号 × 角色档 × 可见空间 × 看板访问 × 启停；重复账号拦截 |
| **项目配置** | 主看板指标行按分区管理；行内改名；⊕ 手动添加分支；**前期数据解绑**（开 = 定义变更不回溯已发生月、历史按原口径封存；关 = 联动刷新历史）；新增项目初始为空（待接源，不编造） |
| **组织架构** | 部门 / 中心 / 个人三层维护，支持组织变化检测 |
| **虚拟分组** | 子PM组、业务线的成员配置 |

配置变更全部写审计。

## 七、数据库与切库

系统同时支持**真库**与**假数库**，用于「正式使用」和「演示 / 培训」两种场景。

### 库选择优先级

```
HCFB_DB 环境变量（forced·锁定后运行时不可切）
   ↓
db_mode 模式文件（记住上次按钮选择，重启后沿用）
   ↓
假数库存在 → 默认走假数库
   ↓
真库 hcfb.db
```

`db()` 每次现取全局 `DB_PATH` 且无连接池，因此 `set_db_mode()` **运行时切库即时生效，无需重启**（`POST /api/dbmode`）。

> ⚠ **切库是全局的**，不是按用户隔离——切到假数库后，所有访问者都会看到示例数据。演示完请切回真库。

### 假数库 `hcfb_demo.db`

由 `seed_demo.py` 生成，已入 git 可直接使用：

| 项 | 数量 |
|---|---|
| `cells` 数据格 | 9317 |
| 台账明细 | 3954 条 |
| 覆盖 | 26 个部门 / 256 个中心（全组织） |

生成规则：

- **只填【系统取数】项，不填任何【BP 手填】项**（`o_bp` / `o_act` / `soc_bp` / `i_cbp` / `i_incr` / 中心预算当量 / 自定义分支 / `fa_hc`）——手填项留给使用者自己体验
  - 因此**中心级「预算当量」故意为空**，中心 / 子PM组的 GAP 卡需手填后才有数，这是设计而非缺数据
- 台账（3.2）与主看板逐行一致：`已入职 → soc_join`；`已offer待入职 → soc_sys(+soc_hs)`；`简历&面试中 → 纯台账`
- 灌数顺序固定（云产品一~五部优先），保证重跑时历史核对过的数字不变

重新生成：

```bash
cd backend && PYTHONPATH=. python seed_demo.py
```

## 八、权限体系

### 角色

**角色是单选的一个「主角色」，没有附加角色这一层。**共三档，决定四个看板的默认权限（0 无 / 1 查看 / 2 编辑）：

| 主角色 | 集团人力预估表 | 预算看板 | 社招滚动台账 | 云智&外包 |
|---|---|---|---|---|
| **HRBP** | 编辑 | 编辑 | 编辑 | 编辑 |
| **招聘经理** | 查看 | 查看 | **编辑** | 查看 |
| **业务** | 查看 | 查看 | 查看 | 查看 |

对应 `admin.html` 的 `ROLE_KB`，可在账号的角色弹窗里单选切换；单个看板的权限也能在此基础上逐项微调（`kbperm`）。

另有两个独立标识，与主角色正交：

| 标识 | 作用 |
|---|---|
| `is_sysadmin` | 系统管理员，可管账号与全局配置，界面上单独显示徽标（不出角色标签） |
| `is_head` | 负责人 |

### 可见范围

按账号配置可见空间（部门 / 中心 / 虚拟分组）。**管理员全量可见**——不受可见空间配置限制。

### 写权限保护

| 机制 | 说明 |
|---|---|
| `require_writer()` | 写操作统一校验，只读角色与停用账号一律拒写 |
| 只读汇总保护 | 集团合计、部门级、业务线、子PM组等汇总空间**禁止直接写入**，只能改其成员或本空间的调节项 |
| 系统管理员防自锁 | 禁止把自己降级 / 停用 / 移除最后一个系统管理员，避免无人能管 |

## 九、校验闸与状态码

服务端强制校验，前端不做最终裁决。CSV / xlsx 导入若有不合格行则**整批拒绝**并回报完整错误清单，不做部分写入。

| 状态码 | 场景 |
|---|---|
| **422** | 备注必填未填、量级异常、参数不合法（最常见，32 处） |
| **404** | 空间 / 年份 / 账号不存在（21 处） |
| **403** | 只读或停用账号拒写、系统数指标拒手填（10 处） |
| **428** | 前置条件未满足（4 处） |
| **423** | 已发生月已锁定，拒改 |
| **410** | 目标已失效 |
| **409** | 冲突（如已通过 `HCFB_DB` 锁库时尝试切库） |
| **400** | 请求格式错误 |

## 十二、部署

当前部署在 AnyDev 云研发环境：

```bash
cd backend
PYTHONPATH=. nohup python3.8 -m uvicorn app:app --host 0.0.0.0 --port 8787 > uvicorn.log 2>&1 &
```

**部署要点**：

- 走打包上传，不是 `git pull`（云端未装 git）
- 真库 `hcfb.db` 不在包内（未被 git 跟踪），部署不会覆盖生产数据——每次部署前后建议核对真库 md5
- 假数库 `hcfb_demo.db` **在**包内，会被新版覆盖（这是预期，它是可重新生成的演示数据）
- 部署前先整体备份 `/data/hrbp-ai`

### 分支约定

| 分支 | 用途 |
|---|---|
| `test` | 主开发分支，改动在此提交，部署以此为准 |
| `dev` | 与 `test` 保持同步（`git push origin HEAD:dev`） |
| `main` | 目前落后，未同步最新功能 |
